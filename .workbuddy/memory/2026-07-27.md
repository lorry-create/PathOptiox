**诊断 chat 客服无法真正调用 LLM（用户填了 DASHSCOPE_API_KEY 仍返回固定回复）**
- 根因1：Uvicorn reload 默认忽略隐藏文件 `.env`（watchfiles 默认 exclude dotfiles），改 .env 不会触发重启 → 运行进程内 `settings.DASHSCOPE_API_KEY` 一直为空 → 走关键词 fallback。已重启后端修复 + 改 main.py 的 uvicorn.run 加 `reload_includes=["*.env", ".env"]` 让 reloader 监控 .env
- 根因2（真正卡住真实调用的原因）：DashScope（阿里云百炼）账户欠费 `Arrearage`，即使 key 加载成功，LLM 调用被 400 拒绝，代码按设计降级到关键词匹配。需用户充值账户解决；充值后无需重启（key 值不变）
- 代码逻辑正确：chat_service.py 第133/189行 `if settings.DASHSCOPE_API_KEY` 分支 + 捕获 Arrearage 降级；默认账号 lorry/123456
- 诊断技巧：用 venv python 直接 `from config import settings` 读 key 值；用 `python -c` 模拟 `chat_service.chat()` 可看到 logger 输出的欠费错误；chat 路由需 Bearer token（先 /api/auth/login 拿 token）

**复核：用户称百炼账户"本身有钱"但仍报 Arrearage —— 排除模型名问题**
- 用用户 key 实测 6 个模型（qwen-turbo/qwen-plus/qwen-max/qwen-long/qwen2.5-7b-instruct/qwen3-0.6b）**全部**返回同样的 `Arrearage`
- 结论：**不是模型用错**（代码用的 qwen-turbo 也没问题），`Arrearage` 是账号级计费拦截，与模型无关
- 真正原因高度怀疑：**当前 key `sk-b8c96...` 所属的阿里云账号 ≠ 用户以为"有钱"的那个账号**（常见：多个账号/子账号 RAM key，充错账号；或看到的是"免费额度"而非实际账户余额；或存在未结清逾期账单导致整账号被置为欠费态）
- 下一步建议：用创建该 key 的同一账号登录 dashscope 控制台核对「费用中心」欠费红条/逾期账单；或直接在该"有钱"账号下新建 key 替换 .env 后让我复测
